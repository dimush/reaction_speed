# Neural voice takes — Chatterbox Multilingual (local, CPU)

This file documents the **raw voice take** generator only. It is deliberately a
separate file from `README.md` so it does not collide with the audio pipeline
agent's edits.

`neural_voices.py` replaces the flat SAPI TTS source material. It writes **only**
to `tool/audio/recordings/`; it never touches `res/raw*`, `synth.py`, or any
part of the SFX / music / DSP pipeline. The character DSP chain
(GRUFF / SQUEAKY / SHOUTY) is applied downstream by the pipeline, not here.

## Install

Dedicated venv, **Python 3.11** (3.12 also works; 3.11 has the widest wheel
coverage for `s3tokenizer` / `spacy-pkuseg`). The system Python is never touched.

```powershell
py -3.11 -m venv tool\audio\.venv-tts
tool\audio\.venv-tts\Scripts\python.exe -m pip install --upgrade pip

# CPU torch FIRST, so chatterbox's `torch==2.6.0` pin is already satisfied by
# 2.6.0+cpu and pip never downloads the ~2.5 GB CUDA wheel.
tool\audio\.venv-tts\Scripts\python.exe -m pip install torch==2.6.0 torchaudio==2.6.0 `
    --index-url https://download.pytorch.org/whl/cpu

tool\audio\.venv-tts\Scripts\python.exe -m pip install chatterbox-tts==0.1.7
```

`tool/audio/.venv-tts/` and `tool/audio/recordings/_alternates/` are git-ignored.

### If pip fails with `CERTIFICATE_VERIFY_FAILED`

This machine runs Norton, which MITM-inspects TLS with a locally generated root
CA that Python's bundled `certifi` does not know about. Do **not** use
`--trusted-host`; instead point pip at a bundle that includes Norton's CA:

```bash
python -c "from pip._vendor import certifi; print(certifi.where())"   # -> CACERT
cat "$CACERT" "C:/ProgramData/Norton/Antivirus/wscert.pem" > ca-bundle.pem
export PIP_CERT=ca-bundle.pem                    # for pip
export SSL_CERT_FILE=ca-bundle.pem               # for the huggingface_hub download
export REQUESTS_CA_BUNDLE=ca-bundle.pem
```

## Regenerating

```powershell
$env:SSL_CERT_FILE="...\ca-bundle.pem"; $env:PYTHONIOENCODING="utf-8"

# 1. voice-prompt reference clips (generated once, then DSP-warped)
tool\audio\.venv-tts\Scripts\python.exe tool\audio\neural_voices.py refs

# 2. the take sweep — resumable, skips any take whose WAV already exists
tool\audio\.venv-tts\Scripts\python.exe tool\audio\neural_voices.py generate

# 3. objective scoring, pick best take per line, write recordings/ + TAKES.md
tool\audio\.venv-tts\Scripts\python.exe tool\audio\neural_voices.py select
#    add --no-asr to skip the whisper-small intelligibility score
```

To re-roll a single line, delete its take files from
`tool/audio/recordings/_alternates/raw/` and re-run `generate`, then `select`.

## Output contract

- `tool/audio/recordings/<line>_<lang>.wav` — the chosen take.
  **Mono, 24 000 Hz, 16-bit PCM**, silence-trimmed, peak-normalised to **−3 dBFS**.
  `lang` ∈ `en` | `de` | `ru`.
- ⚠️ `synth.py` uses `SR_TONAL = 22050` for voices. These takes are **24 kHz**
  (Chatterbox's native rate — deliberately *not* resampled, so the DSP chain
  receives the original signal). **Resample on load.**
- `tool/audio/recordings/TAKES.md` — chosen take per line with its metrics.
- `tool/audio/recordings/_alternates/` (git-ignored) — rejected takes, the raw
  untrimmed generations in `raw/`, the voice-prompt clips in `refs/`, and
  `metrics.json` with every per-take measurement.

## How takes are made and chosen

Five takes per line × 8 lines × 3 languages = **120 generations**. Each take
varies the prompt text (plain / emphatic punctuation / elongated vowels), plus
`exaggeration` 0.80–1.60, `cfg_weight` 0.20–0.50 and `temperature` 0.65–1.00.
High `exaggeration` is always paired with low `cfg_weight`, per Resemble's own
guidance — otherwise the model rambles.

All takes use an `audio_prompt_path` so the voice identity is consistent across
lines *and* languages (the same announcer in en/de/ru). The reference is a
longer neutral sentence generated with the default voice, then resampled to
shift pitch+formants down (×0.82, GRUFF) or up (×1.28, SQUEAKY).

**Very short texts destabilise the model.** An unprompted `"Ready?"` produced
7 seconds of babble in the initial probe. Mitigations: the audio prompt itself
(strongly stabilising), Chatterbox's own repetition/long-tail EOS forcing, and
automatic per-take checks. Selection is fully objective (nobody listened):

- duration inside `0.16·syllables … 0.55·syllables + 0.85` s
- longest internal silence after trimming (catches a hallucinated second utterance)
- clipping fraction
- energy-envelope **syllable nuclei** count vs. expected syllables
- **F0 range** in semitones (autocorrelation pitch track) as an expressiveness proxy
- **`whisper-small` transcript similarity** to the prompt text — a scoring signal
  and tiebreaker only, *never* a sole rejector, because whisper-small is weak on
  one-word utterances, especially in Russian

Trimming only ever removes silence — leading/trailing, or everything after the
first long internal gap. It never tries to extract a word, because there would
be no way to verify the cut landed correctly without listening.

## Runtime on this machine (i5-1235U, CPU-only, 4 torch threads)

| | |
| --- | --- |
| Model load | ~150 s (first run also downloads ~3 GB) |
| Per take | ~35–60 s typical; a runaway generation can reach ~160 s |
| Full 120-take sweep | ~90–110 min |
| `select` pass (incl. whisper-small on every take) | ~10–20 min |

Run `generate` in the background; it prints per-take progress and an ETA, and
it is resumable, so an interruption costs at most one take.
